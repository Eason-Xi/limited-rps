# 限定猜拳 —— FoloToy AI Passport

基于《赌博默示录》（开司）"限定猜拳"的多人联机派对游戏。每位选手手里一台 AI Passport，
在自己的设备上暗中出牌；另有一台 AI Passport 当**庄家**（发牌兼裁判）。

默认的**直连**方式下，设备之间直接无线通信，**不需要电脑，也不需要路由器**：开机就能玩，昵称用手机扫码登记到
设备上。需要大屏看板、对局记录和 CSV 导出时，可以在设置里改用**电脑服务**方式：所有设备连现场 Wi-Fi，经电脑上
运行的 `tools/kj_hub` 联机，电脑看板实时显示每位选手的昵称、剩余的石头 / 剪刀 / 布、星星，以及对决中双方已经
扣下的暗牌。看板只给庄家和观众看，不给选手看。

## 规则（与原作一致）

- 每人开局 **石头、剪刀、布各 4 张**，**星星 3 颗**。
- 两人对决：各自扣下一张牌，同时亮出。石头胜剪刀、剪刀胜布、布胜石头。胜者从败者处拿走
  **1 颗星**，平局不动；出过的牌作废。
- 星星**归零立即出局**。
- **12 张牌全部出完且星星 ≥ 3 颗即过关**；出完但不足 3 颗即**失败**。
- 庄家宣布结束（原作的时限）时，仍有手牌的人判负。

开始一场对决有两种方式：

- **碰拳**：两个人面对面，同时**长按 OK**。庄家按两人按下的时刻配对，双方屏幕显示对手的昵称，
  3 秒倒计时后自动开打；认错人了，倒计时内长按 OK 取消。
- **名单挑战**：在"选择对手"里挑一个空闲的人发起挑战，对方 20 秒内应战。

## 两种联机方式

| | 直连（默认） | 电脑服务 |
| --- | --- | --- |
| 需要什么 | 只要设备 | 2.4 GHz Wi-Fi + 一台运行 `tools/kj_hub` 的电脑 |
| 怎么通信 | 设备之间用 ESP-NOW 直接收发（固定信道，默认 1） | 设备连现场 Wi-Fi，经电脑转发 |
| 登记昵称 | 设备自己开热点，手机相机扫码连上后在网页里填写，昵称存在设备里 | 手机扫码打开电脑上的登记页，昵称存在电脑的登记表里 |
| 看板 | 可选：庄家用 USB 线接电脑，Chrome / Edge 直接打开 `tools/kj_board/index.html` | 浏览器打开电脑服务的看板，可以用带令牌的链接给别的电脑或平板看 |
| 对局记录与 CSV 导出 | 没有 | 有 |

全场设备要用**同一种**方式：两种方式之间互相看不到。在"设置"里切换，确认后设备会重启；首页左上角显示当前方式
（"直连 · 不需要电脑"或"电脑服务已连接"）。

## 需要准备

| 物品 | 说明 |
| --- | --- |
| 每位选手一台 AI Passport | 人数不限；一台庄家最多 128 个座位。 |
| 再多一台 AI Passport 当庄家 | 同一份固件，持有唯一可信的赌局状态。 |
| 每位选手一部手机（可选） | 登记昵称。没有昵称也能玩，屏幕上显示编号（如"07号"）。 |
| 电脑与 Wi-Fi（只在电脑服务方式需要） | 见[用电脑服务联机](#用电脑服务联机可选)。 |

只有两台设备也能玩：一台庄家 + 一位选手，在庄家上添加**电脑选手**陪练。

## 快速开始（直连，不需要电脑）

1. 给每台设备刷入 `build/FoloToy-AI-Passport-full.bin`（见[编译与刷机](#编译与刷机)）。开机直接进入首页，
   左上角显示"直连 · 不需要电脑"。
2. 庄家设备在首页选择"我是庄家 · 开设赌局"。
3. 选手设备选择"我是选手 · 加入赌局"。还没有昵称时先显示**登记昵称**说明页：
   - 按 **OK** 开始登记：设备重启后开出热点 `KJ-XXXX` 并显示二维码。用手机**相机**扫码连上热点，弹出的网页里
     填写昵称（最多 8 个汉字或 16 个字母；没弹出就在浏览器打开 `192.168.4.1`）。设备显示"欢迎"后自动重启，
     直接回到找赌局。手机可以断开这个热点了。
   - 不想登记就**长按 OK** 跳过，以后在"设置 → 登记 / 修改昵称"里再登记。
4. 在赌局列表里选中庄家的赌局（赌局号就是庄家屏幕上的 4 位编号），按 **OK** 入座。
5. 在庄家菜单里"开始赌局"。选手各自碰拳或挑战、对决、守住星星。入座的选手每隔几秒向周围广播自己的昵称，
   对手、碰拳配对、庄家的选手名单上几秒内就会显示出来。

重启后会预选上次的角色；选手会自动回到上次的赌局和座位。想在电脑上看看板，见[直连模式的看板](#直连模式的看板usb)。

## 用电脑服务联机（可选）

1. 在电脑上启动电脑服务，浏览器会自动打开看板：

   ```bash
   python3 tools/kj_hub/hub.py
   ```

   macOS 第一次运行会问是否允许 Python 接受传入的网络连接，选"允许"；Windows 请把当前网络设成"专用网络"。
   详见 [电脑服务说明](tools/kj_hub/README.zh_CN.md)。
2. 每台设备在"设置"里选"改用电脑服务联机"，按 OK 确认，设备重启。
3. **配网**（每台设备只需一次）：还没配过网的设备重启后开出热点 `KJ-XXXX` 并在屏幕上显示二维码。用手机**相机**
   扫码连上热点，弹出的网页里选择现场 Wi-Fi、输入密码（没弹出就在浏览器打开 `192.168.4.1`）。设备连接成功后
   自动重启，之后开机自动连这个 Wi-Fi。推荐自带 2.4 GHz 路由器，电脑最好用网线接入；访客网络、需要网页认证或
   开了"AP 隔离"的 Wi-Fi 通常不行，手机热点只适合少量设备调试。
4. 设备连上 Wi-Fi 后会自动找到电脑服务，首页左上角显示"电脑服务已连接"。
5. 之后和直连一样选角色。没有昵称的选手先显示**登记二维码**：用**微信扫一扫**（或手机相机）打开网页填写昵称；
   手机必须和电脑连同一个 Wi-Fi。在看板或庄家菜单里"开始赌局"，看板实时跟踪每一张牌。

想回到直连：设置里选"改用直连（免电脑）"。

## 设备界面与按键

▲ / ▼ 按下即响应；OK 单击确认；长按 OK（0.5 秒）用于返回、撤回、拒绝、取消——只有手牌页的长按是**碰拳**。
每个页面底部都有本页的按键提示，右上角显示电量（读不到电量计时显示 `--`）。

- **设置**：直连方式下是"登记 / 修改昵称""改用电脑服务联机""返回"，上方显示本机昵称、联机方式与信道、设备编号；
  电脑服务方式下多一项"重新配网"，上方显示 Wi-Fi 与电脑服务地址。
- **碰拳**：从两人里先按下的那一刻起，0.6 秒内另一人也按下就算碰到；庄家在 0.9 秒后结算。只碰到一个人就
  配对；没碰到人提示"没碰到对手"；同一时刻有好几个人在碰拳、分不清谁和谁时提示"人太多，再试一次"。
  电脑选手不参与碰拳。
- **选择对手**只列出此刻空闲且在线的人，真人在前、电脑选手在后，显示昵称。
- 挑战 20 秒无人应战自动作废；对决中一方断线 15 秒，对决作废，双方都不扣牌。
- 庄家屏幕显示汇总（入座、在线、对决中、已离场），"选手名单"里能看到每个人的昵称、状态、星星和剩余手牌数，
  但不显示具体是哪几张牌，可以放在明处。页脚显示看板是否已连上电脑。
- 登记页与热点页屏幕常亮；其他页面 60 秒无操作变暗，第一下按键只负责点亮，有新事件时也会自动点亮。

## 看板

### 直连模式的看板（USB）

直连方式不需要电脑；想要大屏看板时，用 USB 数据线把**庄家**接到电脑，用 Chrome 或 Edge 直接打开
`tools/kj_board/index.html`，点"连接庄家设备（USB）"。不用安装或启动任何服务。选手卡片上显示选手设备广播的
昵称（在设备的设置里修改）；没登记昵称的选手可以在看板上临时起个名字（只存在这台电脑的浏览器里）。
直连方式没有对局记录和 CSV 导出。

### 电脑服务与看板

`tools/kj_hub` 是一个只用 Python 标准库的电脑服务，详见 [电脑服务说明](tools/kj_hub/README.zh_CN.md)：

- **联机中继**：所有设备只和电脑通信（UDP），电脑按设备转发游戏帧；庄家仍是唯一的裁判。
- **扫码登记昵称**：设备显示二维码，手机打开电脑上的登记页；昵称只存在电脑的数据目录里
  （默认 `~/kj-hub-data`），设备用自己的昵称字库显示，显示不了的字在登记时就会提示换掉。
- **看板**：浏览器打开 `http://127.0.0.1:47180/board`。全场公告板、每位选手一张卡片（昵称可以直接改，
  会同步到设备）、开始 / 结束 / 新一局 / 增减电脑选手 / 清空 / 移出、可选时限、对局记录、一键遮挡（H 键）、演示。
  多个赌局时可以在顶部切换。看板只允许这台电脑打开；别的电脑或平板要用服务启动时打印的带令牌链接。
- **采集与导出**：每一局的选手状态和事件都写成 JSONL；服务首页 `http://127.0.0.1:47180/` 可以导出每局的
  选手结果、对局事件和昵称登记表（CSV，Excel / WPS 直接打开中文不乱码）。

## 工作原理

```text
直连（默认）：
  选手设备 ──ESP-NOW 单播（请求 / 心跳）──► 庄家设备 ──USB 串口 "@KJ {json}"──► 电脑看板（可选）
     ▲  │                                      │
     │  └─ESP-NOW 广播（昵称）──► 庄家、其他选手 │
     └──── ESP-NOW 单播（视图）/ 广播（信标）◄──┘

电脑服务：
                                   ┌──────────── 电脑服务 tools/kj_hub ────────────┐
选手设备 ──UDP 47101 信封+游戏帧──► │ 按 MAC 中继 · 发现 · 昵称登记 · 记录 · 看板    │ ◄─HTTP 47180─ 手机（登记页）
   ▲                                │                                               │ ──SSE──► 浏览器看板
   └──────── 庄家的视图 / 信标 ◄─────┤                                               │
庄家设备 ──UDP（游戏帧）+ TCP 47103（"@KJ {json}" 看板行 / "@KJ start" 命令）────────┘
```

- **一份固件，两种角色，两种联机方式。** 庄家运行规则引擎（`main/kj_rules.c`），是唯一可信状态。选手只收到自己
  座位的视图；双方都扣牌之前，对手的牌不会发给任何人。协议逻辑（`main/kj_server.c`、`main/kj_client.c`）与传输
  无关：直连时游戏帧（`main/kj_proto.h`，≤ 64 字节）直接作为 ESP-NOW 载荷收发（`main/kj_radio.c`）；电脑服务时
  套上 24 字节的 hub 信封（`main/kj_hubproto.h`）经电脑转发（`main/kj_net.c`）。联机方式存在 NVS 里，开机时
  决定启动哪一套无线，两套不会同时运行。
- **直连。** 设备以 STA 模式开着 Wi-Fi 但不连任何路由器，固定在同一个信道（menuconfig 的
  `CONFIG_KJ_ESPNOW_CHANNEL`，默认 1）。庄家每秒广播一次信标（阶段 + 可挑战名单），选手据此列出附近的赌局；
  请求、心跳、视图都是单播，由 ESP-NOW 在链路层确认与重传，设备内部用一张 16 项的最近使用对端表突破 ESP-NOW
  20 个对端的上限。
- **可靠性在应用层**：请求带序号与开机号，每 250 ms 重发直到视图确认；庄家按开机号去重，并重发视图直到心跳
  确认版本号；视图带庄家的开机号（epoch），选手丢弃同一次开机里版本号倒退的旧视图（UDP 会乱序）。碰拳请求带
  "在路上多久"，庄家据此还原按下时刻。两种联机方式共用这一套。
- **昵称。** 直连：昵称存在选手自己的设备里。入座后每隔约 3 秒（带随机抖动）广播一次"我是几号、昵称是什么"
  （`main/kj_names.c`），同一赌局的选手和庄家按编号记下来；庄家只认座位登记的那台设备自己报的昵称，并把昵称写进
  看板行。自己的座位变了（重新入座、庄家清空后重新编号）就清空昵称表，几秒内由大家的广播重新填满。电脑服务：
  电脑服务的登记表说了算，设备开机时把本机保存的昵称报上去（登记表丢了可以补回），别人的昵称按（赌局号、编号）
  向电脑查询并缓存。
- **热点网页。** 独立的开机模式：设备开热点，网页服务 + 通配 DNS（弹窗认证）。直连方式用它登记昵称：只开 AP，
  网页提交的昵称在设备上校验（与电脑服务同样的规则：最多 24 字节、显示宽度 16，逐字查昵称字库），保存后重启回到
  游戏。电脑服务方式用它配网：APSTA，新的 Wi-Fi 先实际连上一次才保存。热点与游戏的内存峰值因此隔开。
- **持久化。** 庄家在状态变化后把紧凑快照写入 NVS，掉电重启后恢复赌局；进行中的碰拳 / 挑战 / 对决作废，
  扣下的暗牌退回手中。联机方式、昵称、Wi-Fi、上次的电脑地址也存在 NVS。
- **测试。** 主机测试覆盖规则、碰拳配对、协议（含昵称帧）、直连的昵称表与广播、hub 线协议与客户端、DNS、配网与
  昵称表单、界面状态机，以及两套多设备仿真：直连 25% 丢包（含昵称广播，最后检查每台设备都知道其他人的昵称），
  和经 hub 中继每跳 10% 丢包、重复、乱序，中途重启选手、电脑服务和庄家。电脑服务有自己的单元与集成测试；
  C 与 Python 两边的线协议用同一份黄金向量（`tests/data/kj_hub_vectors.txt`）逐字节对照。

## 编译与刷机

```bash
source <ESP-IDF v5.5.3 路径>/export.sh
./tools/validate.sh            # 主机测试 + 固件编译 + 合并镜像校验
```

从 `0x0` 刷入校验过的合并镜像会**清空设备上保存的数据**（联机方式、昵称、Wi-Fi、庄家保存的赌局），之后设备回到
默认的直连方式：

```bash
python -m esptool --chip esp32c3 -p <串口> -b 460800 write-flash 0x0 build/FoloToy-AI-Passport-full.bin
```

只更新程序、保留已保存的数据时，只写应用分区（用 `validate.sh` 归档在 `build/firmware/<sha256>/` 里的文件）：

```bash
python -m esptool --chip esp32c3 -p <串口> -b 460800 write-flash 0x10000 build/firmware/<sha256>/FoloToy-AI-Passport.bin
```

从 1.1.0（只有电脑服务方式）升级时，没有保存过联机方式的设备会进入直连方式；要继续用电脑服务，在设置里改回即可，
之前配好的 Wi-Fi 还在。

`menuconfig` 的 Limited RPS 菜单里可以改直连信道（全场设备必须一致，只在信道 1 太拥挤时才需要改）、电脑服务方式
的 Wi-Fi 省电（MIN_MODEM 省电但每个包延迟更大，需要实测）。开发时可以在本地（不进仓库的）`sdkconfig` 里设置
`CONFIG_KJ_DEV_WIFI_SSID` / `CONFIG_KJ_DEV_WIFI_PASSWORD`，电脑服务方式下没配过网的设备会直接连这个 Wi-Fi。

## 限制与待验证项

- **没有在实机上验证过：** 直连（ESP-NOW）在真实场地的距离与穿墙、多台设备同时广播时的空中占用与丢包、
  热点登记昵称在各家手机上的弹窗表现；电脑服务方式的 Wi-Fi 联机延迟与稳定性、微信扫一扫打开局域网网页（iOS 上
  可能需要允许微信访问"本地网络"，不行就用手机相机扫码）；两种方式的续航（无线常开，估计 4~5 小时）与碰拳在
  真人手上的时间差。
- 直连方式下所有设备要在同一个信道、彼此在无线范围之内；庄家离开范围时选手会提示"与庄家失联"，回来后自动续上。
  对局记录、CSV 导出和网页看板只有电脑服务方式才有；直连方式的看板只能用 USB 线接庄家。
- 直连方式的昵称没有"不能重名"的检查（没有统一的登记表）；同一个座位的昵称以最后一次广播为准，重新编号后
  可能有几秒显示旧昵称。
- 电脑服务方式下电脑是单点：电脑睡眠或退出，全场暂停；重新启动后设备自动重连，庄家的赌局在设备上，不会丢。
  需要设备之间（经电脑）互通的 2.4 GHz Wi-Fi；开了 AP 隔离、需要网页认证的网络不行。路由器不转发广播时，
  在配网网页的"高级"里填电脑的 IP，或启动服务时加 `--sweep <网段>`。
- 昵称只能用设备字库里有的字：可打印 ASCII、`·`、GB2312 的 6763 个汉字和少量人名常用字；表情符号和繁体字不行。
- 直连方式与 1.0.0 的 ESP-NOW 固件不兼容（协议版本不同），电脑服务方式与 1.1.0 兼容；全场请刷同一版固件。
- 一台庄家最多 128 个座位；选择庄家角色后，重启设备才能改选。
