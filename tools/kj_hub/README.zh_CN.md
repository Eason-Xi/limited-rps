# 限定猜拳电脑服务（kj_hub）

让所有 AI Passport 经现场 Wi-Fi 联机的电脑服务：转发设备之间的游戏帧、给手机提供扫码登记昵称的网页、
把庄家的对局实时推给浏览器看板，并把每一局记录下来、导出 CSV。只用 Python 3.9+ 标准库，不需要安装任何东西。

电脑服务是可选的。固件默认的**直连**方式不需要电脑和路由器（见[项目说明](../../README.zh_CN.md#两种联机方式)）。
要经电脑服务联机，每台设备都在"设置 → 改用电脑服务联机"里切换；设备重启，还没配过网的会开出配网热点。
直连方式下的设备不会连电脑服务。

## 运行

```bash
python3 tools/kj_hub/hub.py
```

启动后终端会打印：

- 本机看板地址 `http://127.0.0.1:47180/board`（会自动用浏览器打开；加 `--no-browser` 不打开）；
- 服务首页 `http://127.0.0.1:47180/`（设备列表、改昵称、清空昵称、导出）；
- 给别的电脑或平板用的看板链接（带令牌 `?k=…`，只给庄家 / 主持人）；
- 本机局域网地址与数据目录。

按 Ctrl+C 停止。电脑服务停止或电脑睡眠时，全场会暂停；重新启动后设备会自动重新找到它。

| 参数 | 说明 |
| --- | --- |
| `--data 目录` | 数据目录，默认 `~/kj-hub-data`。 |
| `--http 端口` | 网页端口，默认 47180（登记页和看板都在这里；设备从 OFFER 里得知）。 |
| `--tcp 端口` | 庄家看板连接的端口，默认 47103（设备从 OFFER 里得知）。 |
| `--udp 端口` | 收设备数据报的端口，默认 47101。固件固定发往 47101，一般不要改。 |
| `--subnet 网段` | 定向广播的网段，例如 `192.168.1.0/24`（默认按本机地址的 /24）。 |
| `--sweep 网段` | 每 15 秒逐个单播通知这个网段的设备。路由器不转发广播时用。 |
| `--bind 地址` | 只在某个网卡上监听，默认所有网卡。 |
| `-v` | 输出调试日志。 |

## 网络要求

- 设备只支持 **2.4 GHz** Wi-Fi。推荐自带一台路由器，电脑最好用**网线**接到这台路由器。
- 设备要能和电脑互通：访客网络、需要网页认证（认证页）或开了"AP 隔离 / 客户端隔离"的 Wi-Fi 通常不行。
- 手机热点只适合少量设备调试（iOS 热点一般只能连 5 台左右）。
- 家用路由器连 30 台以上设备时可能不稳定，人多时用更好的 AP，并确认 DHCP 地址池够用。
- 手机要连**同一个 Wi-Fi** 才能打开登记页。

### 防火墙

- **macOS**：第一次运行会问"是否允许 python3 接受传入网络连接"，选"允许"。如果之前点了拒绝，在
  "系统设置 → 网络 → 防火墙 → 选项"里把 Python 改成允许。
- **Windows**：把当前网络设成"专用网络"，第一次运行时在防火墙提示里允许 Python 访问专用网络。
- 关掉会接管全部流量的 VPN。

## 设备如何找到电脑

1. 设备连上 Wi-Fi 后每秒广播一次 DISCOVER（UDP 47101）；如果记得上次的电脑地址，会和广播交替着直接发过去。
2. 电脑服务回复 OFFER（带网页与看板端口、昵称），也每 2 秒向本网段广播一次 OFFER。
3. 找到后设备每 5 秒发一次保活；12 秒收不到电脑的任何数据就重新寻找。

路由器不转发广播时：在设备的配网网页里展开"高级"，填这台电脑的 IP；或者启动时加 `--sweep 192.168.1.0/24`。

## 昵称登记

- 选手设备没有昵称时（或在"设置 → 登记 / 修改昵称"里），屏幕上显示一个二维码，内容是
  `http://<电脑地址>:47180/j/<一次性码>`。用**微信扫一扫**或手机**相机**扫码，在网页上填写昵称。
- 昵称规则：最多 24 字节、显示宽度最多 16（汉字算 2、字母算 1，大约 8 个汉字），只能用设备字库里有的字
  （`tools/kj_charset.py`：可打印 ASCII、`·`、GB2312 汉字和少量人名常用字），不能和别人重名。显示不了的字会
  逐个列出来，请换一个。
- 一次性码 15 分钟后过期；设备上按 OK 可以换一个新的二维码。
- 登记表以电脑服务为准：在看板或服务首页改名 / 清空后，设备几秒内就会跟着变。设备也会记住自己的昵称，
  换电脑或删掉数据目录后，设备再次连上时会把昵称补回登记表。
- 微信扫一扫打开局域网地址时，可能先提示"非微信官方网页"，选择继续访问即可。iOS 上微信需要"本地网络"权限；
  打不开时用系统相机扫码（会用 Safari 打开）。

## 看板

- 浏览器打开 `http://127.0.0.1:47180/board`。顶部显示庄家是否已连接；同一台电脑服务上有多个赌局时可以切换。
- 能看到所有人的暗牌，**只给庄家和观众看**：看板与管理接口只允许运行电脑服务的这台电脑直接打开；
  别的设备必须用终端里打印的带令牌链接（令牌保存在数据目录的 `config.json`）。
- 选手卡片上的昵称可以直接改，会写回登记表并同步到设备。
- 其余功能与之前的看板相同：开始 / 结束 / 新一局 / 增减电脑选手 / 清空 / 移出、时限、遮挡（H）、演示。

## 数据与导出

数据目录（默认 `~/kj-hub-data`）里有昵称等个人数据，**不要放进仓库**，活动结束后可以整个删掉。

| 文件 | 内容 |
| --- | --- |
| `config.json` | 电脑服务的编号与看板令牌 |
| `registry.json` | 设备 → 昵称登记表（删除的昵称留有"已删除"标记，设备据此清掉） |
| `registry.log.jsonl` | 改名记录 |
| `sessions/<开始时间>_<赌局号>_g<局号>.jsonl` | 每一局的汇总、选手状态变化与对局事件，每行一个 JSON |
| `hub.log` | 运行日志（自动轮转） |

服务首页可以导出 CSV（UTF-8 带 BOM，Excel / WPS 直接打开）：

- **选手结果**：赌局号、局号、编号、昵称、设备、状态、星星、剩余各类牌、胜负平、结局原因；
- **对局事件**：时间、事件、双方编号与昵称、出牌、胜者、对决号、附加值（碰拳配对时两人按下时刻之差）；
- **昵称登记表**。

## 故障排查

| 现象 | 先检查 |
| --- | --- |
| 设备首页左上角是"直连 · 不需要电脑"，看板上没有它 | 设备还在直连方式：设置里选"改用电脑服务联机" |
| 设备一直显示"正在寻找电脑服务" | 电脑服务在运行吗；电脑和设备在同一个 Wi-Fi 吗；防火墙是否放行；路由器是否开了 AP 隔离；试试配网页"高级"里填电脑 IP 或 `--sweep` |
| 设备显示"正在连接 Wi-Fi" | Wi-Fi 是不是 2.4 GHz；密码对不对（设置 → 重新配网）；离路由器太远 |
| 手机打不开登记页 | 手机连的是不是同一个 Wi-Fi；换系统相机扫码；看电脑上的防火墙 |
| 看板显示"庄家未连接" | 庄家设备是否已选庄家角色；庄家页脚是否显示"看板已连电脑" |
| 看板打开是 403 | 不是运行电脑服务的那台电脑：用终端打印的带令牌链接 |
| 设备提示电脑服务版本不同 | 设备固件和电脑服务不是同一版本，都更新到同一版本 |

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `hub.py` | 入口：参数、日志、启动网络线程与网页线程 |
| `wire.py` | 与 `main/kj_hubproto.h` 对应的线协议（与 C 共用黄金向量 `tests/data/kj_hub_vectors.txt`） |
| `core.py` | 核心逻辑：设备表与中继、发现、昵称与登记、看板行解析、记录、SSE（不碰 socket，可测试） |
| `netio.py` | `selectors` 网络循环：UDP 中继 / 发现，庄家看板 TCP |
| `web.py` | 网页：登记页、看板、管理接口（只允许本机或带令牌）、SSE、CSV 导出 |
| `store.py` | 数据目录：配置、登记表、对局记录、CSV |
| `static/` | 登记页、结果页、过期页、服务首页 |

测试：`python3 tests/test_kj_hub.py`（也在 `tools/validate.sh` 里运行）。
